# Coverage review of standalone 0.8.1.0

The review uses the supplied pristine main game DLL, SHA-256 `a87e45cbd187e42e9d64a610850b39edba4896168b14d71ca71c5d32cf9e96ee`, and the complete standalone runtime source. It inventories native dice/RNG consumers and transitive callers, checks every registered await against PE method bytes and call offsets, and inspects native implementations around unresolved consumers. Interface dispatch, external runtime patches and dynamically chosen callers limit what a static graph can establish. Spell and power addressable assets were not supplied; this is a mechanism review, not an execution test of every definition.

## Verified additions

| Native mechanism | Change | Original game behavior retained |
| --- | --- | --- |
| Bardic Inspiration for attacks | Await at `HandleBardicInspirationForAttack` IL0150 | Reaction decision occurs before prompting; native max/advantage selection, notification, condition interruption and spending remain in the original method. |
| Bardic Inspiration for failed saves | Await at `HandleFailedSavingThrow` IL07e9 | Original save modifier and outcome update follow the original inspiration roll. |
| Bardic Inspiration for failed ability checks | Await at `HandleFailedAbilityCheck` IL0138 | Original check totals, trends and outcome update remain native. |
| Replicated rest hit dice | Await at `NetworkingManager.RollHitDieAsync` IL004c | Original native RPC ordering precedes the original local command; actual spending, healing and callbacks remain native. |
| Ordinary and spell shove contests | New await at `CharacterActionShove.ExecuteImpl` IL00a7 and producer for the existing native spell-shove call | Original read-only wrapper chooses the defender’s skill and modifiers; the original final contest retains raw dice, trait filtering, totals, outcomes, notifications and condition use. Positive-count modifier sums stay automatic. |

Bardic prompts use the recipient character for input ownership. The source condition must still belong to that character and retain its native die while input is pending. Forced maximum remains deterministic and does not prompt. The raw replacement applies only to the native inspiration routine; event subscribers and unregistered callers retain their own RNG.

Ordinary Shove has one explicit await exception for its immutable iterator receiver: the body hash, static Boolean roll signature, exact 15-instruction conditional/argument/result-assignment shape, original skip targets and same-iterator Boolean field are verified before installation. Preparation discards that known receiver and reloads only the same iterator at handoff. The original same-side/incapacitated branch remains ahead of the await. The complete extracted original iterator matches unpatched conditional/result baselines, suspension, cancellation and later effect/event behavior. Other nonempty-stack shapes, including Diamond Soul, remain rejected.

## Synchronous paths (0.5.x single-player, 0.6.0.0 multiplayer)

These paths roll inside one synchronous game call, so there is no native coroutine yield directly before the dice. Since 0.6.0.0 they also run in multiplayer when the shared `MultiplayerExtras` setting is on; it is part of every peer's profile fingerprint together with the per-type settings, so mismatched peers cannot share a room. With it off, every path below keeps the game's dice while networked.

While a deferred roll is pending, native TA action coroutines and banter are held at their next yield, and `GameCampaign.UpdateTime` and `GameLocationBattle.Update` are skipped, so neither combat, the battle state machine nor the world-map clock advances. In multiplayer the front entry runs in its own `TA.Coroutine`; it is the only coroutine exempt from the hold, so the native network scheduler claims it exactly like an awaited iterator (admission, owner input, face vector, replay, void-result observation and completion comparison). Replay runs inside the normal native scope; a planning failure, disable, or "Let the game roll" replays the original with game dice. Location teardown drops the pending originals instead of running them against destroyed state.

`IEnumeratorExtensions.ExecuteUntilDone` and `TA.Coroutine.RunUntilIsFinished` drain coroutines synchronously; a modal wait inside them would never complete. A depth guard makes every await and deferral inside such a pump use native dice.

The `sync-sites` suite runs these resolvers, the probe and the queue against the pristine game assembly under real Harmony. The gadget, repeat-save, surprise and turn-end stealth resolvers are compared with the arguments the original game methods themselves pass to the ruleset roll; the `RollSurprise` transpiler is applied to the pristine method. The connected multiplayer suite drives the deferred runner pattern through the actual protocol, transport, broker and scheduler in two- and three-peer rooms.

Outer and deferred plans are scoped: a die from another actor, context or skill inside the replayed call is left to the game instead of revoking the planned dice.

## 0.7.0.0 additions

A replay that makes several native rolls in one synchronous step is planned as a list of parts (`CompositeRolls`). Each part is an ordinary native call planned by the existing planners; its dice are bound to an anchor (the condition or effect the game is processing when it rolls them), set by prefixes/finalizers on `RulesetActor.SaveToCancelCondition`, `ExecuteRecurrentForms` and `RulesetEffectSpell/Power.ApplyEffectOnCharacter`, so a die can never move to another part, and static bonuses are gated to their part. A part the game does not reach leaves its dice unused; a mismatching roll retires the part's dice and stays native. Methods whose logic is repeated by a resolver are pinned by IL hash (`NativeMethodPin`) and refused at load if they differ.

| Mechanism | Boundary | How the native roll is reproduced |
| --- | --- | --- |
| Start of a battle turn | Transpilers on `GameLocationBattle.NextTurn` and `StartFirstTurnOfRound` replace `ActiveContender.StartBattleTurn(round)`; when deferred, the pinned remainder (death check, `NextTurn` for a dead contender, `TurnInitialize` state change) is skipped and replayed together after input | Parts, in `StartBattleTurn` order: start-of-turn conditions (recurring forms, then the save to end them, as `ProcessConditionsMatchingOccurenceType` processes them) and lingering global and light effects from `RefreshEffectsForBattleTurnStart`/`CheckRecurrentEffects`. A cheap gate defers only when some part has a die the player rolls. Proxies controlled by summoned effects keep native dice. Nothing inside a natively started turn defers. |
| Lingering effects outside the turn start | Prefixes on `RulesetEffectSpell/Power.ApplyEffectOnCharacter` and on `RulesetActor.ExecuteRecurrentForms` (end-of-turn occurrence) | The target's `TryRollSavingThrow` and the effect's `ApplyEffectForms` are planned with the original form parameters; forms are planned as if the save failed, so dice of forms a successful save negates are retired unused. Movement and turn coroutines hold at their next step. |

## 0.8.0.0 additions

0.8.0.0 adds three plan features. A **conditional dice group** is asked only when an earlier face decides that the game will roll it (`AskWhen`/`CheckSucceeds`); a skipped group is marked unused and the game's own branch is not altered. **Ready actions** (`OnReady`) run once every face is known and agreed, before the original call resumes, and may rewrite a value the game computed before the await (attack modifier dice). **Game-master dice** (`AddMasterDice`) are enemy/NPC dice that are not bound to a character the player controls; they are planned only with **Also ask for enemy and NPC dice** on and, while networked, are entered by the host. A spell effect proxy (Flaming Sphere, a summoned weapon, a moving Moonbeam) resolves to the character in `ControllerGuid` for party membership, settings and multiplayer ownership.

| Mechanism | Boundary | How the native roll is reproduced |
| --- | --- | --- |
| Attack modifier dice (Bless, Bane and similar) | The existing attack await sites; `AttackBonusDice.Plan` after the d20 descriptor | A `toHitTrends` entry whose source type and name match exactly one die-valued `FeatureDefinitionCombatAffinity` of the attacker (and no other to-hit trend from that source), with a magnitude that fits its dice, is asked with the d20 (since 0.8.1.0 without the die flag, which the game does not send between players). A ready action replaces the trend value, `ActionModifier.AttackRollModifier` and the call's `rollModifier` argument before the original reads them. Inconsistent trends, foreign modifiers or more than eight dice keep the game's sum. |
| Traps and hazards | Prefix replacing `FunctorEnvironmentEffect.Execute` with an equivalent iterator (pinned `MoveNext`); the two public `TriggerEnvironmentEffect` overloads run unchanged, their private final call is captured | Per affected character, `TryRollSavingThrow` with a null caster and `ApplyEffectForms` with the original source-less form parameters, anchored to that character. Sphere damage shared by several targets is asked once (`targetIndex` 0), as the game caches it. When nothing is manual the captured call runs immediately. New setting **Traps and hazards**; part of the multiplayer fingerprint. |
| Lingering hazards | Prefix on `RulesetEffectEnvironment.ApplyEffectOnCharacter` (pinned) | Same parts as lingering spell effects, with the environment's null source. |
| Spell effect proxies | `RuntimeRolls.Controller` hook | The proxy's dice are planned as the controller's; the native proxy remains the rolling actor. |
| Dispel Magic | Transpiler on pinned `RulesetImplementationManagerLocation.ApplyCounterForm` | One d20 per counterable effect above the automatic level, with the caster's spellcasting bonus shown. No prompt when every effect ends automatically. |
| Bardic penalty die | Transpiler on pinned `RulesetCharacter.OnConditionAdded` | A detrimental condition that uses the source's Bardic Inspiration die (no successful save) asks the source character for that die. |
| Item's last charge | Transpiler on pinned `RulesetCharacterHero.UseDeviceFunction`; the slot-preservation outer site resolves it | The d20 for an item that is destroyed on a 1 when a cast or power use spends its last charge. |

| Random behaviour at turn start | Transpiler on pinned `BattleState_TurnInitialize.Begin` as a turn-start part | The behaviour die of Confusion-style conditions, with the condition's ranges in the prompt, and the condition's save to act (**Repeat saves**). |

| Travel ambush | The existing ambush resolver | The creatures' best `ComputePerceptionScore` as one master d20 against the lookout. |
| Food found | Conditional group after the food search check | The yield dice are asked only when the entered check succeeds. |

| --- | --- |
| Weapon/spell attacks | Registered native action attacks, including repeats/reactions at the listed sites. Predefined results remain native. Combat-affinity modifier dice (Bless, Bane) are asked with the d20 since 0.8.0.0; other random modifiers calculated before the await remain automatic. |

## Automatic native boundaries retained deliberately

- Concentration remains native in multiplayer and on break-concentration paths that make no roll (unconscious, substitute forms).
- Shove contests with positive-count ability-affinity modifier sums remain automatic. Such dice can change the feature-driven Athletics/Acrobatics defense choice; the preview traps them before any RNG. Zero/negative-count sums retain the original empty-loop behavior, supporting normal advantage-only native providers. The supported producer previews the original wrapper for both actors and stops its final contest before events or dice. The defender’s displayed skill is the selected defense; the raw trait binding preserves the original game routine’s acting-skill argument and selected-defense proficiency.
- Diamond Soul retries in `HandleFailedSavingThrow` IL0633 and IL0690 were independently evaluated. Adding their offsets directly caused the strict await preflight to reject an argument block branching outside its capture region. The ternary has a setter receiver below the native roll arguments. Those candidates were removed; the safety guard was retained.
- Saves triggered by damage taken while a turn starts natively, the knock-out save of Relentless Rage-style features, rage-end exhaustion saves, save rerolls when a condition is gained and the hit dice regained by a death save's stabilisation keep the game's dice. In single-player a corner notice reports party d20s the game rolls itself.
- Stored condition dice, random condition durations, regeneration amounts, a forced concentration check from a spell, random form/condition selection, random motion, batches mixing damage with healing, loot, encounter tables and AI choices are not claimed manual.
- Unknown providers, foreign modified preview helpers, unsupported actor controllers and incompatible rule mods remain outside the qualified native producers.

## Evidence boundaries

The native Bardic and Shove fixtures execute copied original compiled IL under the real Harmony generator and production dice adapter; they declare UI, services, inventory/armor and condition spending as boundaries. The Shove matrix compares the original selected skill, totals, outcomes and event payloads across both defending skills and every advantage/disadvantage pair, and rejects positive-count modifier sums before RNG. Side and incapacitation mutations invalidate accepted faces. The separate complete original Shove iterator fixture verifies native conditional skips, Boolean result assignment and subsequent effects around the new await. The independent coverage suite checks registered method hashes and original call offsets against the actual PE image. The await suite generates and installs the full patched coroutine set using genuine game dependencies, distinguishing the two CoreCLR-incompatible Unity InternalCall methods from the test-only getter-shim generation check. Actual Windows/Unity/Photon multiplayer acceptance remains required for release certification.
